#+title: unquote
#+subtitle: A lightweight comma markup for editors, rendered to HTML with Guile Scheme

/unquote/ lets writers and editors fill structured HTML templates without
writing HTML, brackets around blocks, quotes or attributes.  Commands start
with a comma, the way Scheme's =unquote= escapes out of a quoted template;
indentation marks children.  Every command is an ordinary Guile procedure
that returns SXML, so the person maintaining the templates works in plain
Scheme.

#+begin_example
,recipe
  ,title Cheeseburger Helper
  ,photo[cheeseburger-jar.jpg][A half-gallon jar of layered pasta and spices]
  ,yield 1 half-gallon or 1 half-pint (see tip)

  ,ingredients
    ,ul
      4 cups pasta (small shells or elbow macaroni)

      ,frac[1/2] cup whole milk powder

  ,tip
    If you want to keep the pasta with all the other ingredients, you'll
    need a half-gallon jar.  See our ,link[https://example.com/jars][jar guide].
#+end_example

* Requirements

GNU Guile 3.0 or later.  No other dependencies.

* Usage

Render a document.  =--tags= adds a component module to the generic
=(uq tags)=; =-L examples= puts the example modules on the load path:

#+begin_src sh
guile -L . -L examples unquote.scm --tags "(recipe tags)" examples/recipe/recipe.uq > recipe.html
guile -L . -L examples unquote.scm --expr --tags "(recipe tags)" examples/recipe/recipe.uq   # also print the intermediate Scheme
#+end_src

Or compile with a per-project Guile script.  =examples/recipe/build.scm=
turns =recipe.uq= into a complete HTML page (doctype, =<title>= taken from
the first heading) and works from any directory:

#+begin_src sh
examples/recipe/build.scm                        # recipe.uq -> recipe.html
examples/recipe/build.scm other.uq out.html
#+end_src

Run the tests:

#+begin_src sh
guile -L . -L examples tests/run.scm
#+end_src

* Editor syntax

** Commands
- A command is a comma followed by a name: =,tip=, =,em=.
- A comma is a command only at the start of a word (start of line, or after
  a space, =(= or =[=) and when a letter follows.  =salt, pepper=,
  =salt,pepper= and =1,000= are plain text.
- Unknown commands are errors with a line number.

** Blocks
- A block command starts its own line.  Indented lines below it are its
  children.
- In most blocks (=,tip=, =,ul=, …), a blank line separates groups: a new
  paragraph, or a new list item.  Lines of one group join with spaces, so
  editors can wrap freely.
- Text after the command on the same line is the first line of its body.
- Some blocks (=,title=, =,yield=, …) hold one run of text.  Wrapped lines
  join; a blank line or a nested block inside one is an error.

** Lists
#+begin_example
,ul
  First item, which may wrap
  onto a second line

  Second item
  ,ol
    A nested item

    Another

  ,li
    An item with two paragraphs.

    The second paragraph.
#+end_example

** Tables
Rows are =,tr= commands.  Inside a row, each blank-line group is a cell;
a cell that is just a =,th= is a header cell.  A cell may wrap across
lines and may hold a list.

#+begin_example
,table
  ,tr
    ,th Ingredient

    ,th Amount
  ,tr
    Pasta (small
    shells)

    4 cups
#+end_example

Text directly inside =,table=, outside any =,tr=, is not turned into a
row; it produces invalid HTML.

A table can also be written column by column, which =,columns= turns
into rows.  Each =,column= is written like a =,tr=: blank lines separate
its cells.  Short columns are padded with empty cells.

#+begin_example
,columns
  ,column
    ,th Ingredient

    Pasta

    Salt
  ,column
    ,th Amount

    4 cups

    ,frac[1/2] tsp
#+end_example

** Inline commands
- =,em[some words]= covers exactly the bracketed text.  Brackets nest and may
  span lines; balanced brackets inside are plain text.
- Without brackets an inline command takes the rest of the line
  (=,em Optional:=), and a word command takes the next word (=,frac 1/2=).
  Either way, punctuation touching the text is included: write
  =,frac[1/2],= when a comma or period follows.
- A =[= that does not directly follow a command name is plain text, so
  =[sic]= is safe.

** Links, images and other attribute commands
- Some commands take an attribute bracket first, as in HTML, then an
  optional text bracket: =,link[address][text]=, =,image[file][alt text]=,
  =,photo[file][alt text]=.  A link without text shows its address.
- The main value -- the address, the file, a QR code's data -- is the first
  word, or can be named: =,link[:href https://…][text]=,
  =,image[:src lid.svg][lid]=, =,qr[:data …]=.  Give it once, one way or
  the other; a second plain word is an error (quote values with spaces).
- Most commands that take attributes can leave the brackets out when no
  attributes are needed.  Some, such as =,link=, =,image= and =,photo=,
  require them; leaving them out (or empty) is an error with a line
  number.
- Words in the attribute bracket are separated by spaces.  A plain word is
  passed to the command, which decides what it means (for =,link=, the
  first one is the address).
- =:name value= sets an attribute by name: =,link[:href https://… :title
  Sizes][jars]=, =,photo[jar.jpg :width 3in][A jar]=.
- A value with spaces goes in double quotes, as in Scheme or SXML:
  =:title "Jar sizes for every recipe"=, =,photo["jar photo.jpg"][A jar]=.
  =\"= and =\\= are escapes.  Quotes are only special in attribute
  brackets; in prose they are plain text.
- A quoted value must close on the line it opens on.  The words of an
  attribute bracket may be spread over several lines, but a single value
  may not.

** Attributes are rarely needed
Editors normally write none: classes, labels and sizes live in the
component definitions.  =:name value= is there for the occasional case.

* Defining components

=(uq tags)= provides the generic components: =p=, =ul=, =ol=, =li=,
=table=, =tr=, =td=, =th=, =columns=, =column=, =em=, =strong=, =link=,
=image= and =frac=.  Anything specific to a
kind of page goes in a module of its own; =examples/recipe/tags.scm=
defines =(recipe tags)= with =recipe=, =title=, =photo=, =yield=, =prep=,
=ingredients=, =directions= and =tip=.

Each component is a procedure returning SXML, registered with a kind.
=define-tag= also exports it from the module it appears in.

| kind                    | placement   | content                                                     |
|-------------------------+-------------+-------------------------------------------------------------|
| =block= (=block:block=) | own line    | groups split by blank lines, each wrapped in =#:wrap= (=p=) |
| =block:inline=          | own line    | one run of inline content                                   |
| =inline= (=inline:inline=) | mid-line | without brackets, the rest of the line                      |
| =word= (=inline:word=)  | mid-line    | without brackets, the next word                             |

#+begin_src scheme
(define-tag block        (tip . body)   `(aside (@ (class "tip")) (h3 "Tip!") ,@body))
(define-tag block:inline (title . body) `(h1 ,@body))
(define-tag block        (ul . body) #:wrap li `(ul ,@body))
(define-tag block        (li . body)    `(li ,@body))
(define-tag inline       (em . body)    `(em ,@body))
(define-tag inline       (link . body) #:required-attributes attrs
  (let ((href (main-attribute attrs 'href 'link)))   ; :href or the one plain word
    `(a (@ (href ,href) ,@(attribute-list attrs '(href))) ,@body)))
#+end_src

=#:attributes var= lets a command take =[attributes][text]=; the brackets
may be left out, giving no attributes.  =#:required-attributes var= is the
same, except that the attribute bracket must be there and not empty: the
parser reports =line N: ,link needs attributes: …= otherwise.  It cannot
know /which/ attribute is needed, so a component that needs a particular
one checks for it, usually with =main-attribute=.  In both cases =var= is
bound to the attribute bracket as a list: plain words as strings, in order,
and =:name value= pairs as =(name "value")=, ready to splice into an SXML
=(@ …)=.  So =[jar.jpg :width 3in]= gives =("jar.jpg" (width "3in"))=, and
=body= is the text.  Helpers from =(uq parse)=:

- =(main-attribute attrs 'name 'command)= — a command's main value, given
  as =:name= or as the one plain word.  Missing, given both ways, or given
  as several plain words is an error naming the command, with its line:
  =,link takes one href; quote it if it has spaces=.  =link=, =image=,
  =photo= and =qr= use it.
- =(attribute attrs 'name [n])= — the value of =:name=, else the /n/th
  plain word, else =#f=.
- =(attribute-values attrs)= — the plain words.
- =(attribute-list attrs ['(excluded …)])= — the =:name value= pairs as SXML
  attributes.

=#:wrap= names the tag each blank-line group is wrapped in.  The wrapper's
own kind decides what a group may hold: a =block:inline= wrapper (=p=) holds
a run of text, and block lines stand on their own; a =block= wrapper (=li=)
holds everything up to the next blank line, nested blocks included.

=#:wrap= also takes a list, =#:wrap (td th)=: the first tag wraps each
group, and a group that is just one of the listed tags -- a lone =,th= in
a row -- is left as it is.  (A single tag always passes itself through: a
lone =,li= in a list is not wrapped in another =li=.)  =#:wrap #f= means
no wrapper: the block's text stays inline, groups joined by a space, as
in a table cell:

#+begin_src scheme
(define-tag block (tr . body) #:wrap (td th) `(tr ,@body))
(define-tag block (td . body) #:wrap #f `(td ,@body))
#+end_src

Where a block has no =#:wrap=, and at the top level of a document, loose
text goes in the /default wrapper/: the block tag declared with
=#:default-wrap #t=.  =(uq tags)= declares =p=:

#+begin_src scheme
(define-tag block:inline (p . body) #:default-wrap #t `(p ,@body))
#+end_src

A project can declare another; the latest declaration wins.  If none is
declared, loose text is an error with its line number.  The parser itself
names no component.

The two keywords combine, in either order.  A list that takes attributes:

#+begin_src scheme
(define-tag block (steps . body) #:wrap li #:attributes attrs
  `(ol (@ (class "steps") ,@(attribute-list attrs)) ,@body))
#+end_src

#+begin_example
,steps[:id fill]
  Fill the jar

  Seal it
#+end_example

Since =#:attributes= is optional, =,steps= alone works too: no
attributes, and text after it on the line is the first line of its body.

* QR codes (optional)

=(uq qr)= adds a =,qr= command.  It needs [[https://github.com/artyom-poptsov/guile-qr-code][Guile-QR-Code]] and the Guile-Lib
it uses (on Guix: =guix install guile-qr-code=); nothing else in unquote
depends on them.  Load it like any tags module: =--tags "(uq qr)"=, or
=#:tags '((uq qr))=.

#+begin_example
Scan ,qr[https://example.com/recipes/cheeseburger-helper][the recipe online].

,qr["WIFI:T:WPA;S:Kitchen Net;P:secret;;" :ecc high][Kitchen Wi-Fi]
#+end_example

- The data is the first word in the attribute bracket, or =:data=: any text -- a URL,
  digits, a =WIFI:= or =mailto:= string, a vCard.  Quote it if it has
  spaces or brackets, and write line breaks as =\n= inside the quotes.
- =:ecc= sets the error correction: =low= (the default), =medium=,
  =quartile= or =high=.
- The text bracket is the accessible name (=aria-label=); without one,
  the data is used.
- The result is an inline =<svg class="qr">= with a quiet zone, scaled
  to whatever size CSS gives it.

* Build scripts

=(uq compile)= compiles =.uq= files to HTML.  The output is a fragment;
whatever goes around it -- doctype, head, site header -- is ordinary SXML
in the build script, passed as =#:page=:

#+begin_src scheme
(use-modules (uq compile))

(compile-uq "recipe.uq" #:tags '((recipe tags)))   ; -> recipe.html, a fragment

(define (page recipe)
  `(html (@ (lang "en"))
     (head (meta (@ (charset "utf-8")))
           (title ,(page-title recipe)))
     (body (header (a (@ (href "/")) "Recipes"))
           (main ,@recipe))))

(compile-uq "recipe.uq" #:tags '((recipe tags)) #:page page #:indent #t)
#+end_src

- =#:out= sets the output file; the default replaces =.uq= with =.html=.
- =#:tags= lists extra component modules, loaded before parsing.
- A document has no root element: its top-level blocks are written as
  siblings.  =#:page= receives them as a list of SXML nodes, to splice
  with =,@=.
- =#:page= is a procedure from the document's nodes to the SXML to write.
  If its result is an =html= element, an HTML5 doctype is added; anything
  else is written as a fragment.  =page-title= gives the text of the first
  =h1=, for the =<title>=.
- A project's tags module may redefine a generic component (=em=, =p=,
  …); later =#:tags= modules take precedence.
- =#:indent= (=#t= for two spaces, or a number) writes indented HTML
  instead of one long line.  Indentation is added only where it cannot
  change the rendering: elements whose children are all elements are
  broken onto lines, neighbouring inline elements stay together on one
  line, and anything containing text, inline markup or =pre= is written
  as is.  =examples/recipe/build.scm= uses it.
- On success =compile-uq= prints =IN -> OUT= and returns =OUT=.  On an
  error it prints =FILE: line N: message=, writes nothing and returns =#f=.

Lower-level pieces are exported too: =uq-file->expr=, =uq-file->sxml=,
=component-module=, =page-title=, =write-html= and =write-sxml=
(=sxml->xml= with an optional =#:indent=).
=examples/recipe/build.scm= is a complete script.

* Scheme expressions in a document

A comma followed by an open parenthesis is an escape into Guile Scheme:
=,(expr)= evaluates one expression and puts its value where it stands.
It is for the template maintainer, not for editors.

#+begin_example
Makes ,(number->string (* 4 3)) jars.  Updated ,(strftime "%B %Y" (localtime (current-time))).
#+end_example

** Where it can go
Anywhere an inline command can: at the start of a word in a paragraph or
list item, on a block's own line, or inside a text bracket
(=,em[a ,(string-upcase "b") c]=).  The expression may span lines, and
brackets or quotes inside it are ordinary Scheme -- =,em[,(string-append
"]" "[")]= works.  Attribute brackets are literal: an escape there is not
evaluated.

** What the value may be
| value                               | written as                                    |
|-------------------------------------+-----------------------------------------------|
| a string                            | text, escaped                                 |
| a number                            | its printed form                              |
| an SXML element, or a list of nodes | markup: =,(em "x")=, =,(quote (b "x"))=        |
| =#f=                                | nothing                                       |
| anything else                       | its printed form, e.g. =#<unspecified>=: avoid |

Calling a component directly, as in =,(em "x")=, bypasses the parser's
rules: =,(ul …)= in the middle of a paragraph produces a =<ul>= inside a
=<p>=, which is invalid HTML.  Use markup for structure.

** What it can see
The document is parsed first and evaluated afterwards, as one expression,
in a module that uses Guile's core bindings, =(uq tags)= and every
=#:tags= module.  So an escape can call any procedure those export,
components included.  Inside the =markup= macro (below) it also sees the
variables in scope where =markup= is written.

** Expressions only
An escape is an expression inside the document, not a top-level form, so
it cannot hold definitions: =,(define jars 12)= is reported as
=definition in expression context=.  Put helpers and data in a tags
module or the build script and call them from the document.  Do not rely
on the order in which escapes run.

** Errors
An escape that is not a complete expression is a parse error with its
line number: =line 3: ,( is not a complete Scheme expression (unbalanced
parentheses?)=.  An error /while evaluating/ an escape -- or raised by a
component, such as =photo='s check for a file -- is reported with the
line it came from too: =recipe.uq: line 7: ,photo needs its src: …=.  The
parser wraps every component call and escape so that it can; =--expr=
shows the expression without those wrappers.  Markup embedded in a Scheme
file with =markup= or =#m<<END= reports that file and its lines:
=site.scm: line 12: …=.

** Trust
An escape can run any Scheme code with the permissions of whoever builds
the site.  Only build documents you trust, or evaluate them in a module
that exports nothing beyond the components.

* Using markup inside Scheme

#+begin_src scheme
(use-modules (uq parse) (uq tags) (recipe tags))

(define jars 12)
(define card
  (markup ",tip
  Makes ,(number->string jars) jars. Keep them ,em[dry]."))
#+end_src

=markup= expands at compile time into ordinary calls, so parse errors stop
compilation and =,(expr)= sees the variables in scope.  With
=(enable-markup-reader!)= the same text can be written as a =#m<<END= …
=END= heredoc without quotes.  See =examples/demo.scm=.

See [[*Scheme expressions in a document][Scheme expressions in a document]] for what =,(expr)= can do.
