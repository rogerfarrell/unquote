#+title: Notes for coding agents

This file is for AI coding agents (and humans) changing this repository.
Read README.org first for what the project is and the editor syntax.

* Purpose and audience

/unquote/ has two audiences with opposite needs:

- Editors and writers, who are not programmers.  Their syntax must stay
  lean: commas for commands, indentation for children, brackets only for
  inline extent and attributes.  Attributes are rare, by name (=:width 3in=)
  or as plain words the component interprets.  No quotes, no block closers.
- The template maintainer, who writes components in Guile Scheme.

Changes that add syntax for editors need the maintainer's agreement.
Prefer moving complexity into components or the parser.

* Layout

| path               | contents                                                   |
|--------------------+------------------------------------------------------------|
| =uq/parse.scm=     | reader, parser, registry, =define-tag=, =markup= macro     |
| =uq/tags.scm=      | generic components: structure, lists, inline markup        |
| =uq/compile.scm=   | =compile-uq= and helpers: .uq file -> HTML, for build scripts |
| =uq/qr.scm=        | optional =,qr= component; needs Guile-QR-Code            |
| =unquote.scm=      | command-line renderer (=--tags= adds component modules)    |
| =tests/run.scm=    | regression tests: markup -> expected HTML or error         |
| =examples/recipe/= | =(recipe tags)=, =recipe.uq= and its =build.scm= script   |
| =examples/demo.scm= | markup embedded in Scheme                                 |

* Commands

#+begin_src sh
guile -L . -L examples tests/run.scm             # must print "all tests passed"
                                                 # (QR tests run only if Guile-QR-Code is on the load path)
guile -L . -L examples unquote.scm --tags "(recipe tags)" examples/recipe/recipe.uq         # render
guile -L . -L examples unquote.scm --expr --tags "(recipe tags)" examples/recipe/recipe.uq  # show intermediate Scheme on stderr
examples/recipe/build.scm                        # compile recipe.uq -> recipe.html (git-ignored)
guile -L . -L examples examples/demo.scm         # embedding demo
#+end_src

Use =--no-auto-compile= if stale compiled files in =~/.cache/guile= get in
the way.  Requires Guile 3.0.

* How a document becomes HTML

1. =port->tree=: lines become an indentation tree.  A blank line takes the
   indent of the next non-blank line.  Tabs count as four spaces.
2. =block-head=: a line starting with =,name= for a registered block kind
   is a block; everything else is text.
3. =convert-block= / =convert-children=: =block:inline= tags take one run
   of text; =block:block= tags split their body at blank lines and wrap
   each group in their =#:wrap= tag (default =p=).  The wrapper's kind
   decides what a group may hold.
4. =parse-inline=: each run is parsed once, lines joined with newlines, for
   inline commands, brackets, attributes and =,(expr)= escapes.
5. The result is one Scheme expression, =(list …)=: the top-level blocks
   as siblings, with no root element.  It is evaluated in a module that
   uses the component modules and written with =write-html=.

The tag registry is global and filled when a component module loads, so
component modules must be loaded before a document is parsed.

* Invariants

- Kinds are exactly =block:block= (alias =block=), =block:inline=,
  =inline:inline= (alias =inline=) and =inline:word= (alias =word=).
  Aliases are resolved in =register!=; code after registration only sees
  canonical names.
- The parser and compiler must not name components or validate a
  particular one.  Behaviour comes from declarations: kinds, =#:wrap=,
  =#:default-wrap=, the attribute options.  Checks that concern one
  component live in that component.
- The default wrapper (for loose text where no =#:wrap= applies, and at
  the top level) is whichever block tag was last declared with
  =#:default-wrap #t=; =(uq tags)= declares =p=.  With none, loose text
  is a parse error.
- Only =block:block= tags take =#:wrap=, and the wrapper must be a block tag.
  =#:wrap= is a tag, a list of tags (the first wraps; a group that is a
  lone listed tag passes through), or =#f= (no wrapper: text stays inline,
  neighbouring inline groups joined by a space).  The registry stores
  =unset=, =inline= or a list; =wrap-of= turns =unset= into the default.
  Wraps do not cascade: an implicit wrapper gets the group's content
  directly, without applying its own =#:wrap=.
  =#:wrap= combines with either attributes option, in any order.
- =#:attributes var=: optional; without brackets the command gets ='()=,
  inline or block.  =#:required-attributes var=: the parser rejects a
  missing or empty bracket with a line number.  It cannot check for a
  particular attribute, so components check the ones they need.  For a
  command's main value use =main-attribute= (=:key= or the one plain word,
  with uniform errors), as =link=, =image=, =photo= and =qr= do.
- Attribute commands read =[attributes]= first and an
  optional =[text]= second.  The attribute bracket parses to a list of
  plain-word strings and =(name "value")= pairs; components interpret it.
  Values may be "double-quoted" Scheme strings (read with =read=, never a
  :key).  A quoted value must close on its own line; the bracket matcher
  skips quoted strings in attribute brackets only, and stops at a line
  break inside one.
- =,(expr)= escapes are skipped whole by the bracket matcher, so brackets
  in their strings do not count; an unreadable one is a parse error with
  its line.  Escapes are not evaluated in attribute brackets.
- =uq-error-message= (in =(uq parse)=, re-exported by =(uq compile)=)
  must never raise: errors come in several shapes (=syntax-error=,
  =misc-error=, …) and a format mismatch falls back to the raw key and
  arguments.
- Errors that know their line are raised under the key =uq-error= (via
  =oops= or =located=).  The parser wraps every component call and
  =,(expr)= in =((@ (uq parse) at-line) LINE NAME (lambda () …))= with =call=
  or =wrap-line=; =at-line= turns any other error into a =uq-error= with
  that line, and lets =uq-error= through, so the innermost line wins.
  New code that emits a call must go through =call= so it gets a line.
  =strip-line-wrappers= removes the wrappers for display (=--expr=).
- =at-line= also sets the =current-command= parameter to NAME (escapes pass
  #f and keep the enclosing one), so components and =main-attribute= can
  name the command in messages without being told.
- Markup embedded in Scheme reports the Scheme file's lines: the =markup=
  macro takes them from =syntax-source=, the =#m= reader passes line and
  file explicitly, and =markup-string->exprs= sets =current-uq-file= so
  messages name the file.  =compile-uq= leaves it unset and adds the file
  name itself.  =uq-error= has an exception printer, so uncaught errors
  show the message.
- Find the end of a datum read from a string with =read-datum-at=, not
  =ftell=: string ports count bytes, so =ftell= is wrong after non-ASCII.
- Parse errors are raised with =oops= and start with ="line N: "=.  Report
  the line where the problem starts (where a bracket opened, not where the
  run started).
- Open every file with an explicit encoding (=#:encoding "UTF-8"= or
  =set-port-encoding!=).  Guile's default comes from the locale, which is
  ASCII under C/POSIX; =.uq= files and output are always UTF-8.  The
  tests include a non-ASCII round trip, so run them under =LC_ALL=C= too.
- Error messages are ASCII only: Guile's error port may print other
  characters as =?=.
- Do not name a module =(unquote …)=.  =define-module= quasiquotes its
  arguments, so =(unquote parse)= is read as =,parse=.  The modules live
  under =(uq …)= for that reason.
- Keep =(uq tags)= generic and free of dependencies beyond Guile.  Components
  that need a library go in their own module, as =(uq qr)= does, and their
  tests skip when the library is missing.
- WeasyPrint renders inline SVG in isolation: page CSS does not apply
  inside it, nor does =currentColor= inherit the page's =color=.  CSS in a
  =<style>= inside the SVG does (=(uq qr)='s =qr-css=).  Checked against
  WeasyPrint 70 by reading the PDF's colour operators.
- Components for a particular kind of page go in
  their own module under =examples/= (or the user's project), using
  =(uq parse)= and, for helpers such as =plain=, =(uq tags)=.
- =define-tag= exports the component from the
  module they appear in; do not add a separate export.
- =write-sxml #:indent= must never change rendering.  Only elements that
  are not phrasing or =pre=-like and whose children are all elements get
  line breaks; runs of phrasing siblings share a line.  Check changes by
  comparing minified and indented pages in a browser (text and pixels).
- =compile-uq= writes a fragment.  It does not grow options for page
  furniture (head, stylesheets, language): those belong in the build
  script's =#:page= procedure.  =write-html= adds a doctype only when the
  root is =html=.
- Components return SXML.  =sxml->xml= writes empty elements as =<x />=,
  which browsers read as an open tag for non-void elements; =write-sxml=
  therefore closes empty non-void elements (=<td></td>=).  Write HTML
  through =write-sxml=/=write-html=, not =sxml->xml= directly.

* Known issues

- An inline command with nothing after it at the end of a line (=a ,em=
  then a newline) produces an empty element, written as =<em />=.  It
  should be a parse error.
- Mixed tabs and spaces are not detected and can mis-nest silently.
- There is no escape for a literal word that starts with a comma.

* Making changes

- Add or update a case in =tests/run.scm= for every behaviour change, and
  run the tests before committing.
- If the HTML for =examples/recipe/recipe.uq= changes, say why in the commit.
- Keep the editor-facing rules in README.org in step with the parser.
- New source files get the GPL-3.0-or-later header used in the existing
  files.
